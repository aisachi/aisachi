## Engineering approach

I prefer evidence over attractive claims.

- **State the uncertainty.** A timeout, a missing event, or a passing test does not automatically prove the conclusion we want.
- **Define the boundary.** What is being tested, under which assumptions, and which conditions remain unverified?
- **Design for failure.** Consider ambiguous outcomes, invalid inputs, stale evidence, and safe stopping behavior.
- **Review what tools produce.** AI-assisted implementation is useful; responsibility for interpretation and honest reporting still matters.
- **Keep sensitive work private.** Public documentation is intentionally separated from private code, configurations, credentials, and operational details.
